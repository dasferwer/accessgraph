# AccessGraph

Сервис отношений и наследуемых прав на папки и документы. Поддерживает владельцев,
редакторов, участников команды и вложенность объектов; возвращает решение и путь,
по которому получено право. Кеш не задерживает отзыв доступа.

## Семантика

- `folder:*` и `document:*` могут иметь `owner` или `editor`: пользователя либо команду.
- `team:*` содержит пользователей через `member`. Вложенные команды не поддерживаются.
- Отношение `parent` связывает документ или папку с родительской папкой.
  Права распространяются вниз по всем родительским связям, но не вверх.
- `POST /check` проверяет право редактирования. И владелец, и редактор получают его.
  Неизвестный объект или пользователь получает отказ; явных запретов нет.
- Циклы запрещены. Мутации сериализуются блокировкой строки версии в PostgreSQL,
  поэтому две конкурентные операции не могут по отдельности пройти проверку
  и совместно создать цикл.

Стек: Python 3.11+, FastAPI, PostgreSQL 17, Redis, psycopg, pytest.
`graph.py` содержит обход и проверку циклов, `api.py` — операции и кеш,
`db.py` — схему. Версии зависимостей закреплены в `uv.lock`.

## Отзыв доступа и кеш

Каждое изменение отношений увеличивает версию в той же транзакции. Проверка
читает версию и отношения из одного снимка первичной БД. Ключ Redis включает
версию: старый положительный результат недоступен новым проверкам после отзыва.
TTL 60 секунд нужен для очистки старых ключей, а не для распространения изменений.

Гарантия: запрос, начавший чтение версии после подтверждённого удаления отношения,
учитывает удаление сразу, без периода ожидания TTL. Уже выполнявшийся запрос
может вернуть решение из прежнего снимка. Между проверкой права и действием
в другом сервисе остаётся обычная гонка: для атомарной авторизации изменения
нужно согласовать версии с владельцем объекта. Недоступность Redis приводит
к расчёту по БД; недоступность PostgreSQL не разрешает доступ по старому кешу.

## Запуск и демонстрация

```sh
docker compose up --build -d
curl -H 'X-API-Key: local-demo-key' http://localhost:8091/health
python3 scripts/demo.py
```

Демо создаёт команду, папку и вложенный документ, прогревает кеш, удаляет участника
и проверяет немедленный отказ следующего запроса. Имена уникальны для каждого
запуска. Docker публикует порты только на localhost. Демо-ключ и пароль перед
внешним развёртыванием нужно заменить; TLS настраивается на входном прокси.

## Примеры

```sh
curl -X POST http://localhost:8091/relations \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"resource":"folder:docs","relation":"owner","subject":"user:alice"}'
curl -X POST http://localhost:8091/relations \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"resource":"document:readme","relation":"parent","subject":"folder:docs"}'
curl -X POST http://localhost:8091/check \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"user":"user:alice","resources":["document:readme","folder:docs"]}'
curl -X DELETE http://localhost:8091/relations \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"resource":"folder:docs","relation":"owner","subject":"user:alice"}'
```

До 100 объектов в пакетной проверке. Повторная запись или удаление отсутствующего
отношения не меняет версию. Цикл возвращает 409, неправильные типы — 422,
неверный ключ — 401. Интерактивная схема — `/docs`.

## Тестирование

Нужны `uv`, PostgreSQL и Redis из Compose:

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
```

Тесты создают отдельные схемы PostgreSQL. Проверяются наследование, направление
прав, циклы, конкурентные изменения, повтор операций, отзыв после прогрева
настоящего Redis и работа при недоступности кеша. CI запускает PostgreSQL и Redis
и выполняет те же проверки. Остановка: `docker compose down`.

## Ограничения

Стенд ограничен 10 000 отношениями; некешированная проверка загружает граф в память.
Версия общая для графа: любое изменение делает все старые результаты неактуальными,
что снижает эффективность кеша при частых записях. Это сознательный выбор в пользу
простой проверяемой семантики отзыва. Нет отдельных арендаторов, ролей оператора,
аудита изменений и раздельных прав чтения/редактирования. API-ключ доверен сервису,
а идентификатор проверяемого пользователя передаёт вызывающая сторона.
