# AccessGraph

Сервис отношений и наследуемых прав на папки и документы. Поддерживает владельцев,
редакторов, участников команды и вложенность объектов; возвращает решение и путь,
по которому получено право. Кеш не задерживает отзыв доступа.

## Семантика

- `folder:*` и `document:*` могут иметь `owner` или `editor`: пользователя либо команду.
- `team:*` содержит пользователей через `member`. Вложенные команды не поддерживаются.
- Отношение `parent` связывает документ или папку с родительской папкой.
  Права распространяются вниз по всем родительским связям, но не вверх.
- `POST /check` проверяет право редактирования. И владелец, и редактор получают его.
  Неизвестный объект или пользователь получает отказ; явных запретов нет.
- Циклы запрещены. Мутации сериализуются блокировкой строки версии в PostgreSQL,
  поэтому две конкурентные операции не могут по отдельности пройти проверку
  и совместно создать цикл.

Стек: Python 3.11+, FastAPI, PostgreSQL 17, Redis, psycopg, pytest.
`graph.py` содержит обход и проверку циклов, `api.py` — операции и кеш,
`db.py` — схему. Версии зависимостей закреплены в `uv.lock`.

## Отзыв доступа и кеш

Каждое изменение отношений увеличивает версию в той же транзакции. Проверка
читает версию и отношения из одного снимка первичной БД. Ключ Redis включает
версию: старый положительный результат недоступен новым проверкам после отзыва.
TTL 60 секунд нужен для очистки старых ключей, а не для распространения изменений.

Гарантия: запрос, начавший чтение версии после подтверждённого удаления отношения,
учитывает удаление сразу, без периода ожидания TTL. Уже выполнявшийся запрос
может вернуть решение из прежнего снимка. Между проверкой права и действием
в другом сервисе остаётся обычная гонка: для атомарной авторизации изменения
нужно согласовать версии с владельцем объекта. Недоступность Redis приводит
к расчёту по БД; недоступность PostgreSQL не разрешает доступ по старому кешу.

## Запуск и демонстрация

### Бюджеты мутаций

Все три операции изменения отношений устанавливают транзакционные
`statement_timeout` и `lock_timeout` до обращения к строке версии, включая
её создание для нового арендатора. По умолчанию один SQL-запрос ограничен
2000 мс, ожидание блокировки — 500 мс. Настройки
`MUTATION_STATEMENT_TIMEOUT_MS` (1–30000) и `MUTATION_LOCK_TIMEOUT_MS`
(1–10000) задаются в окружении; бюджет блокировки должен быть меньше SQL-бюджета.
Неверная конфигурация останавливает запуск приложения.

При тайм-ауте API возвращает 503 с причиной после отката всей транзакции:
отношения, версия и аудит остаются прежними, даже если batch уже выполнил
часть изменений. Клиент может повторить запрос; повторы изменений идемпотентны.
Это ограничения отдельных SQL-запросов и ожиданий блокировок, а не общий
deadline HTTP-запроса или всей batch-операции. Лимит batch остаётся 100 добавлений
и 100 удалений. `tests/test_mutation_timeouts.py` проверяет реальные блокировки
PostgreSQL, задержанный SQL, откат и сохранение актуального решения кеша.

```sh
docker compose up --build -d
curl -H 'X-API-Key: local-demo-key' http://localhost:8091/health
python3 scripts/demo.py
```

Демо создаёт команду, папку и вложенный документ, прогревает кеш, удаляет участника
и проверяет немедленный отказ следующего запроса. Имена уникальны для каждого
запуска. Docker публикует порты только на localhost. Демо-ключ и пароль перед
внешним развёртыванием нужно заменить; TLS настраивается на входном прокси.

## Примеры

```sh
curl -X POST http://localhost:8091/relations \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"resource":"folder:docs","relation":"owner","subject":"user:alice"}'
curl -X POST http://localhost:8091/relations \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"resource":"document:readme","relation":"parent","subject":"folder:docs"}'
curl -X POST http://localhost:8091/check \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"user":"user:alice","resources":["document:readme","folder:docs"]}'
curl -X DELETE http://localhost:8091/relations \
  -H 'X-API-Key: local-demo-key' -H 'Content-Type: application/json' \
  -d '{"resource":"folder:docs","relation":"owner","subject":"user:alice"}'
```

До 100 объектов в пакетной проверке. Повторная запись или удаление отсутствующего
отношения не меняет версию. Цикл возвращает 409, неправильные типы — 422,
неверный ключ — 401. Интерактивная схема — `/docs`.

## Тестирование

Нужны `uv`, PostgreSQL и Redis из Compose:

```sh
cp .env.example .env
set -a
. ./.env
set +a
uv sync --frozen
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
```

Тесты создают отдельные схемы PostgreSQL. Проверяются наследование, направление
прав, циклы, конкурентные изменения, повтор операций, отзыв после прогрева
настоящего Redis и работа при недоступности кеша. CI запускает PostgreSQL и Redis
и выполняет те же проверки. Остановка: `docker compose down`.

## Изоляция и разрешения

API-ключ определяет арендатора. `API_KEY` сохраняет совместимость с областью
`default`; `TENANT_KEYS` содержит JSON вида `{"alpha":"local-alpha-key","beta":"local-beta-key"}`.
Для Compose передайте эту переменную сервису API. Произвольный `X-Tenant` не
меняет область ключа. Ревизии, отношения, аудит и ключи кеша разделены по арендатору.
Старые отношения при обновлении остаются в `default`.

`POST /check` принимает `permission`: `view` (по умолчанию), `edit` или `manage`.
`viewer` даёт просмотр, `editor` — просмотр и редактирование, `owner` — все три
разрешения. Права наследуются вниз по папкам. Команды могут включать другие команды;
циклы запрещены и для команд, и для дерева ресурсов.

`POST /relations/batch` принимает списки `additions` и `removals` до 100 элементов
каждый. Удаления выполняются перед добавлениями; весь пакет фиксируется одной
транзакцией и одной ревизией. Ошибка цикла откатывает весь пакет и аудит.
`GET /audit?after=0&limit=100` возвращает журнал изменений текущего арендатора.

`min_revision` в проверке позволяет потребовать версию не старее известной;
если она недоступна, ответ 409, а не решение по старым данным. Для обычного
отзыва проверка, начавшаяся после коммита удаления, читает новую ревизию первичной
БД. Уже выполнявшаяся проверка может завершиться по предыдущему снимку.

Рекурсивный SQL выбирает предков запрошенных ресурсов и членство пользователя,
после чего Python строит объяснение решения. Все отношения каталога не загружаются
в память. `visited_edges` показывает размер выбранного подграфа. Индексы покрывают
поиск по ресурсу и субъекту; `UNION` завершает обход даже при цикле в повреждённых данных.

## Ограничения

Для одного запроса допускается подграф до 10 000 отношений и SQL-бюджет 2 секунды;
превышение возвращает 413 или 503, не ложный отказ в правах. У всего каталога прежнего
лимита 10 000 нет. Большой достижимый граф всё ещё может быть дорогим: лимит выдачи
не заменяет бюджет исполнения SQL.

Изменение арендатора инвалидирует весь его кеш; другие арендаторы не затрагиваются.
Записи одного арендатора сериализованы блокировкой его ревизии. API-ключ является
сервисным: имя проверяемого пользователя задаёт доверенная вызывающая сторона.
Нет отдельной аутентификации конечных пользователей, отрицательных разрешений,
условий по атрибутам и очистки аудита. Имена арендаторов и ключи задаются оператором;
не назначайте один ключ нескольким арендаторам.
